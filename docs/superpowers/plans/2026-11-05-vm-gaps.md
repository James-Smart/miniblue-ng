# VM Gaps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `azurerm_linux_virtual_machine` work end-to-end against miniblue by adding NICs, managed disks, richer VM reads, PATCH updates, power endpoints, extensions, SSH public keys and script-only custom data.

**Architecture:** Extend the existing per-service `chi` + `store.Store` handlers. NICs live in the existing `network` package, extensions in the existing `vm` package, and disks/SSH keys get new packages. VM writes use a shared recursive merge that preserves generated fields, and VM create/update/delete synchronise NIC links and disk attachments. No new runtime backend is introduced.

**Tech Stack:** Go 1.26, `github.com/go-chi/chi/v5`, the existing in-memory/file/Postgres store, the `docker` CLI, `golang.org/x/crypto/ssh` (already indirect).

**Spec:** `docs/superpowers/specs/2026-11-05-vm-gaps-frontdoor-design.md`

## Global Constraints

- Go 1.26, existing `chi` routing and `store.Store` patterns. No new framework.
- No new direct dependency except `golang.org/x/crypto/ssh`; run `go mod tidy`.
- `PUT` and `PATCH` both merge over existing records and preserve generated/read-only fields unless explicitly replaced.
- Generated values (private IPs, MAC addresses, disk names, SSH keys) must be stable across GETs.
- Internal fields use the `_` prefix and never appear in API responses.
- Power actions (`start`, `powerOff`, `restart`, `deallocate`) succeed without Docker and update metadata; `runCommand`, logs, service deploy/list/delete and SSH still return `409 DockerUnavailable` without Docker.
- API status conventions: `PUT` 201 create / 200 update, `PATCH` 200, `DELETE` 202 (VM remains 204), list `{"value":[...]}`.
- Verification command for every task: `go test ./...` (plus `go vet ./...` before the final commit).

## Review Focus

- **Docker-less provider update path:** a VM update that power-cycles the VM must work without Docker while runtime-only operations still fail cleanly. Pinned by `TestVMPowerActionsWithoutDocker` in Task 8.
- **Provider read-modify-write:** a NIC or disk GET followed by a full PUT must not lose allocated IPs, MAC addresses, VM links, `managedBy`, `timeCreated` or `diskState`. Pinned by `TestNetworkInterfacePUTPreservesGeneratedFields` in Task 1 and `TestVMDiskAttachmentRoundTrip` in Task 6.
- **Unknown VM property blocks:** boot diagnostics, security profile, spot settings and other blocks must survive PATCH/PUT. Pinned by `TestVMPatchPreservesUnknownPropertyBlocks` in Task 5.
- **Custom data safety:** `#cloud-config` must be skipped and a failing shell script must not fail VM creation. Pinned by `TestVMCustomDataStubMode` and the Docker integration test in Task 11.
- **Extension/SSH secrecy:** protected extension settings must not be returned, and a generated SSH public key must not be regenerated by a later PUT. Pinned by `TestVMExtensionProtectedSettingsHidden` in Task 9 and `TestSSHKeyGeneratedKeyStable` in Task 10.
